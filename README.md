#  CompostingBucket - 堆肥桶
>*腐草为萤！*
---

## 功能概览
`astrbot_plugin_composting_bucket` 的新工作流程是：

1. **上下文丢弃 / 压缩触发**  
   - 当对话达到长度上限、或进入框架内的「上下文压缩」阶段时，  
     这些本该被**直接丢弃**或**仅以摘要形式保留**的内容，会被标记为「可堆肥」数据。
2. **投递到“堆肥桶”**  
   - 原始内容 / 压缩后的内容并不会立刻消失，而是被「堆肥桶」插件接管并存档。  
   - 它们确实已经**不在当前上下文里**了；  
     它们被**安全地移入了一个专门的存放区**。
3. **统一的存储与管理**  
   - 堆肥桶会为这类“对话垃圾”打上时间戳、会话 ID等元数据，  
     并以统一结构存储，方便检索、筛选与后期处理。  
4. **通过开放 API 再利用**  
   - 插件为这些堆肥数据提供相对完善的管理与开放 API：  
   - 这些原本被视为“垃圾”的信息，有机会在其他场景中**化腐朽为神奇**：  
     例如用于统计分析、行为建模、记忆回放、个性化配置调优等等。
5. **数据是无价的，先留着再说**  
   - 我们事先并不知道这些被抛弃的上下文**未来究竟会被用来做什么**，  
     但可以确定的是：  
     > 一旦删除，就再也没有机会。

## 后记
`astrbot_plugin_composting_bucket` 是一个专为 AstrBot 编写的插件。

它的前身只是一个「简单的上下文丢弃策略」实现：<br>
丢弃最旧的x轮对话，保持上下文在模型的输入限制范围内。<br>
如今，这一基础能力已经并入 AstrBot 本体框架内，这个插件也迎来了全新的任务。
---
在多数对话系统中，上下文处理往往非常粗糙——  
**超过上限，就直接丢弃。**

稍微好一些的做法，是在丢弃前做一轮「压缩」，  
比如摘要旧对话、只保留关键信息，再放入长期记忆。 

对于工具型智能体，这也许问题不大；  
但对于**情感陪伴类智能体**，这真的是合理的设计吗？

从今天开始，一切都要改变！
